# 睡岗检测素材与阈值标定

## 素材结论

- 输入：`D:\Coding\fwwsva\test2.mp4`
- 规格：1920×1080、30 FPS、约 42 分 50 秒、固定教室机位。
- 画面中有多人长期读写，适合作为“普通低头”的困难负样本。
- 本轮人工回看没有发现足够明确的趴桌睡眠区间，因此该素材不能单独证明召回率。

## 基线与问题

只使用 `pitch_proxy_deg >= 18°` 且持续 8 秒的基线，在每 2 秒抽一帧的全片粗扫中产生 51 次告警。高密度复检确认，代表性告警主要来自持续读写、侧身以及姿态关键点错配。

## 首轮参数

```text
pitch_threshold_deg = 28
max_head_offset_deg = 50
activity_window_seconds = 3
activity_threshold = 0.18
desk_rest_face_ratio = 0.04
desk_rest_wrist_ratio = 0.35
sleep_seconds = 5
recovery_seconds = 2
```

活动量使用肩宽归一化后的肘/腕滚动位移。正面低头姿态满足机位几何约束且上肢活动量足够低时，才向多帧状态机输入睡眠信号。脸部低于双肩线且贴近手腕的 `desk_rest` 属于强几何证据，不使用容易受横向趴姿关键点抖动影响的活动门控。

## 正样本 `test3.mp4`

- 规格：720×1280、30 FPS、约 23.07 秒、单人近景。
- 原逻辑因趴桌时脸部低于双肩线，将大量帧判为几何无效，告警为 0。
- 增加 `desk_rest` 后识别 338 帧趴桌姿态，在 10.93 秒产生 1 次睡眠事件，抬头后进入恢复并在 16.77 秒回到正常。
- 19.70 秒后的再次趴伏到视频结束不足 5 秒，只进入 `SUSPECTED`，符合持续时间门限。
- 最终参数重新跑上述四个 `test2.mp4` 负样本区间，告警仍全部为 0。

以上是首轮近景原型参数的结果。长课堂素材加入后，默认配置调整为更保守的 `10 秒 + 所有姿态均要求有效静止证据`；因此 `test3.mp4` 的短趴伏在当前默认配置下只进入 `SUSPECTED`，不再产生正式告警。

## 第三轮：姿势初筛 + 眼部确认级联

接入 Open Model Zoo 的 `open-closed-eye-0001.onnx` 后，判定顺序调整为：

1. `28°` 姿势异常先进入候选；
2. 眼睛清晰时使用 2 秒 PERCLOS 窗口，闭眼比例达到 0.60 后持续 3 秒确认；
3. 眼睛不可用时采用远景姿态时间窗：8 秒内低头/伏桌候选占比至少 0.35、低活动严格姿态占比至少 0.15，再按布控规则的 `thresholdMs` 持续确认；短正样本和验收 Demo 使用 5 秒，test6/test8 长课堂负样本使用 15 秒。严格俯角门槛为 `28°`。肩宽小于 80 像素的远景人体活动量门槛为 0.35，近景/中景恢复为 0.18；
4. 姿势正常人员每 0.2 秒做一次眼部质量探测，只有双眼间距至少 40 px 才运行闭眼模型，用于覆盖闭眼后仰。

12 px 初版门槛在 `test6.mp4` 产生 61 个眼部误报。假事件眼距最大为 38.36 px，而 `test4.mp4` 两个真事件眼距为 33.20 px 和 69.03 px。为优先控制课堂远景误报，默认门槛定为 40 px，只保留高质量近景事件。

| --- | --- | --- | ---: | --- |

单元测试增至 20 项，覆盖眼部低频调度、闭眼比例平滑、眼睛短时丢失宽限、姿势候选与最终确认分离以及原有姿态/活动/四态逻辑。

## GPU 环境与性能

- GPU：NVIDIA GeForce RTX 4080 Laptop GPU，12GB。
- PyTorch：`2.11.0+cu128`，`torch.cuda.is_available() == True`。
- 原型默认 `device=0`；依赖文件不再安装 CPU-only PyTorch。
- ONNX Runtime GPU：`1.26.0`，CUDA 执行回退被禁用；眼部模型在 RTX 4080 Laptop GPU 上验证通过。
- 同一 `test3.mp4 / YOLO11n-pose / 640 / no-video` 条件下，CPU 平均推理约 29.77ms，GPU FP32 约 19.48ms，约 1.53 倍加速。
- `test4.mp4` 全帧级联处理约 42 FPS；眼部分类本身很小，候选裁剪一次通常低于 1ms。远景样本会在眼距检查阶段直接返回，不运行 ONNX 网络。
- 三个长视频并行粗扫时平均模型推理约 13.8–14.8ms；该数据受并发影响，只用于扫描，不作为正式单路性能结论。

## Pose ONNX 导出一致性

`yolo11n-pose.pt` 已导出为固定 `640×640`、FP32、opset 17 的 ONNX，模型输出形状为 `[1,56,8400]`。使用 `test3/test4/test6/test7/test8` 各 5 个均匀抽样帧，在 PyTorch CUDA 与 ONNX Runtime CUDA 上进行同一预处理、NMS 和逐检测匹配：

- 25 帧中未匹配检测数为 0；
- 最低匹配 IoU 为 0.7562（来自置信度约 0.39 的画面边缘截断人员）；
- 高置信度检测框最大坐标差为 0.265 px；
- 高置信度关键点最大坐标差为 0.740 px；
- 检测置信度最大差为 0.00123，关键点置信度最大差为 0.00192。

验收阈值为检测 IoU 至少 0.70、高置信度坐标差不超过 1 px、置信度差不超过 0.02，本轮结果通过。完整原始张量中的低置信度候选差异只作为诊断数据，不作为检测级验收条件。

## C++ 服务端到端验收

2026-09-02 在 WSL `Ubuntu-22.04-easySVA` 中使用 GPU 构建进行了独立端口验收：Pose 与眼部 ONNX Session 的启动日志均为 `provider=CUDA`，未启用 CPU Execution Provider 回退。

为避免 MP4 流复制时关键帧寻址造成的素材时间偏移，先将 `test4.mp4` 的 35–60 秒精确重编码为 25 秒验收片段。Python GPU 基准在该片段上检出 1 次睡岗事件；同一片段通过 MPEG-TS/UDP 送入 C++ 服务后结果为：

- 374 条 `detect.frame` 上报，无丢帧、无 POST 失败；
- 状态覆盖 `NORMAL -> SUSPECTED -> SLEEPING -> RECOVERING`；
- 生成 1 组生命周期事件，同一 `eventId` 各 1 条 `start` 和 `end`；
- 正样本为 `trackId=2`，最高闭眼概率约 0.78，最终证据源为 `eye`；
- 循环播放导致的第二次命中被 120 秒重启冷却拦截，未重复创建告警生命周期。

C++ 构建后 3 项 `ctest` 全部通过。同时补充了 HTTP 监听端口失败检查：端口被占用时明确记录错误并退出，不再虚假报告“启动成功”。

2026-09-03 针对 `test9.mp4` 的远景多人课堂画面补充了姿态时间窗。原逐帧严格姿态在关键点抖动下最长仅连续约 3.7 秒。检测候选阈值从 0.35 降到 0.15 后，30–53 秒片段的目标数由 432 增至 555；最终全片 C++ GPU 回归获得 310 条检测帧、2985 个目标、20 个 `SLEEPING` 状态帧，并产生一组完整的 `start/end` 生命周期。为避免把近景低头写字误判成静止，活动门槛按肩宽自适应：远景保持 0.35，近景/中景使用 0.18；姿态回退的最终确认时长不再硬编码，而是读取每个布控规则的 `thresholdMs`。test6/test8 的误报截图表明，长时间托腮或伏案写字会被 Pose 判成 `desk_rest`，因此 15 秒生产规则还要求当前帧持续满足严格姿态，任一写字动作都会重置确认计时；5 秒的 test3 与验收 Demo 继续使用时间窗抗抖。最终线上连续观察约 2 分钟，仅 test3 产生正式告警，test6/test8 为 0。眼部证据可用时的优先级和 3 秒确认逻辑保持不变。

## 剩余边界

现有素材已经能满足原型的正样本、负样本、边界样本和长时误报测试，但不能直接当作训练集：目前只有视频级标签，没有逐人框、时间段和睡眠/清醒标注。

当前级联已经覆盖 `test4` 的近景闭眼后仰，但仍无法恢复 `test5` 远景遮挡中不存在的眼睑像素和稳定单人轨迹。若验收要求 `test5` 也必须检出，需要部署更近机位或训练专用远景睡岗检测模型，并增加逐人框、时间段与状态标注。

级联算法的 C++ 移植、CUDA 推理、帧事件上报和告警生命周期已打通。剩余工作是按实际验收机位复核阈值，并在前后端联调时确认告警展示、持久化和视频回放。
